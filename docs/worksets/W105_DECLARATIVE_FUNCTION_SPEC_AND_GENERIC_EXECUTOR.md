# W105 Declarative Function Spec And Generic Executor Refactor

Status: `planned`

## Purpose

Operationalize [ODR-FN-004](../decisions/ODR-FN-004-declarative-function-spec-and-generic-executor.md):
move OxFunc to a layered behaviour model where each Excel quirk is declared once on a
declarative `FunctionSpec` (grown out of `FunctionMeta`) and every execution path is derived
from it — by one generic executor at runtime and generated specializations at build time —
so the multi-path dispatch drift becomes structurally impossible and the spec becomes the
inspectable, formally-modelable description of the library.

The seam this addresses, observed live: a function's behaviour is currently restated across
the calc-dispatch chain (`eval_*_calc_dispatch`), the generated by-index table
(`surface_dispatch_by_index_generated.rs`), and the XLL scalar table
(`eval_surface_q_unary_number`). Keeping those in sync by hand produced the
`EXP`/`COSH`/`SINH`/`DEGREES` scalar-table guard gap (fixed `4d90246`) and the
`SIN`-rides-by-index-while-`COS`/`TAN`-ride-calc-dispatch inconsistency.

`real_result_policy` / `ArgDomainGuard` (`4d90246`) is the landed prototype of the target
shape: one named closed-enum policy on the meta, read at every dispatch site. This workset
generalizes that pattern to the remaining behavioural axes and collapses the parallel paths.

`.beads/` owns live readiness and blockers.

## Current Checkpoint

2026-06-19:

1. ODR-FN-004 written and indexed in `docs/decisions/README.md`.
2. The behavioural-axis prototype is landed (`4d90246`): `ExcelRealPolicy` promoted from a
   per-function const to `FunctionMeta::real_result_policy`, a closed-enum policy
   (`PASS`/`FINITE`/`SATURATE_SIGN`/`CIRCULAR_TRIG` over `ArgDomainGuard` + `NonFinite`), read at
   all three dispatch sites. 14 functions override the `DEFAULT_REAL_RESULT_POLICY`; the rest
   carry the default. `FunctionMeta` stays `Eq` (named guard, no free `f64`).
3. The three-path drift is documented from a code trace: `eval_shared_unary_numeric_calc_dispatch`
   shadows the generated `eval_*_surface` arms for `COS`/`COSH`/`TAN`/`EXP`/`SINH`/`DEGREES`/…
   (those arms are dead), while `SIN` (absent from the chain) is served live by the by-index
   table. The XLL `Q`-scalar path is a distinct ABI surface and is retained.

## Open Lanes

1. **Cross-surface equivalence law (do first).** A generic test over the spec table asserting
   `scalar(x) ≡ array_lift([x]) ≡ xll_scalar(x)` for the unary-numeric family, plus
   "every overflowing kernel declares a non-`PASS` `real_result_policy`". This is the
   behaviour-preservation harness for every later migration.
2. **Unary-numeric pilot.** Build `execute(spec, …)` for the family; verify the two prep helpers
   (`eval_unary_numeric_surface` vs `eval_unary_numeric_calc_surface`) are equivalent for it;
   route the whole family (including `SIN`) through one path; delete
   `eval_shared_unary_numeric_calc_dispatch`; have the by-index generator emit interpreter calls.
3. **Widen `FunctionMeta` → `FunctionSpec`** one closed-enum axis at a time (arg preparation,
   lift/broadcast, error algebra, precision/rounding), each with a `DEFAULT_*`, behind the
   equivalence law.
4. **Spec-driven generators.** Flip the by-index and XLL-scalar table generators to consume the
   spec rather than hand-written arms; add the "interpreter ≡ generated" equivalence test.
5. **`function_spec!` macro + spec export.** Introduce a defaulting macro to retire the
   all-literal field-add sweep, and extend the registry-metadata CSV export with the new axes as
   the inspectable / diff-across-Excel-releases artifact.
